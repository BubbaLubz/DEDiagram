# Memory: AI-Generation Metrics & Guardrails

Session notes on quantifying claims about DEDiagram's AI generation/edit pipeline. Covers what was measured, how, and the corrections made along the way so future sessions don't re-derive or re-assert stale numbers.

## Eval scripts (in `DEDiagrams/server/eval/`)

- **`ambiguousPrompts.js`** — Tests how `/api/generate` handles 20 curated ambiguous/underspecified prompts (e.g. `"pipeline"`, `"ML real-time sync monitor analytics"`, `"kafka spark s3"`). For each prompt, calls the live Anthropic API twice: once without `SKIP_CLARIFICATION` (should ask clarifying questions) and once with it (should build a sensible pipeline anyway). Run with `node server/eval/ambiguousPrompts.js` (makes 40 real API calls, real cost).
- **`editPayloadSize.js`** — Measures the token/byte savings from `/api/edit`'s field-level slimming of node/edge objects before serializing them into the prompt. Uses Anthropic's `messages.countTokens` (no completion generated, negligible cost) against a real 9-node/9-edge template from `client/src/data/templates.js`.
- **`server/lib/generatePrompt.js`** — extracted from `server/index.js` as the single source of truth for `SYSTEM_PROMPT`/`extractJSON`, so eval scripts exercise the actual production prompt instead of a duplicated copy that could drift.

## Results (as of 2026-07-11)

| Metric | Result | Method |
|---|---|---|
| Ambiguity-detection rate | 100% (20/20) | No-skip calls correctly returned `needsClarification` every time |
| Sensible-default rate | 95% (19/20) | Skip-clarification calls built a valid, schema-compliant pipeline; 1 failure used `componentType: "grafana"`, which isn't in `shared/component-types.json` |
| Edit payload size reduction | ~40% bytes / ~34% input tokens | Slim node/edge fields vs. simulated full ReactFlow v11 runtime shape, on the "Modern Data Stack" template |

## Important corrections / caveats

- **The "grafana" eval failure isn't a real production failure.** `/api/generate` and `/api/edit` both sanitize `componentType` against `VALID_COMPONENT_TYPES` and silently fall back to `rest_api` for anything unrecognized (`server/index.js` ~line 400 and ~565). The eval script calls the Anthropic API directly and does NOT replicate this sanitization step, so it scores raw model output against a stricter bar than what a user actually sees. It's still a meaningful signal (model hallucinated outside its vocabulary), just not a "the app broke" event.
- **There is no diff-based edit mode.** An earlier draft bullet claimed `/api/edit` "serializes only diff-relevant canvas topology instead of full regeneration." That's not what the code does: the client sends the *entire* current diagram every time, and `EDIT_SYSTEM_PROMPT` explicitly instructs the model to "Return the COMPLETE updated diagram JSON — all nodes and edges, not just the changes." The only real optimization is **field-level slimming** (dropping ReactFlow runtime-only fields like `width`, `height`, `selected`, `dragging`, `positionAbsolute`, edge `markerEnd`) — not diff-based editing. The accurate bullet: *"Cut `/api/edit` request payload by ~40% (~34% fewer input tokens) by serializing only essential node/edge fields instead of full ReactFlow node objects."*
- **The "full ReactFlow shape" baseline in `editPayloadSize.js` is a reasoned estimate**, not captured from a live browser session — there's no browser-automation tooling (Playwright/Puppeteer) in this repo. It's based on documented ReactFlow v11 behavior (fields a node/edge picks up after one render + one drag). The token counts themselves are exact (real Anthropic tokenizer), but the "full" side of the comparison is a reconstruction, flagged as such.

## ERD (Entity-Relationship Diagram) feature (added 2026-09-12)

Each pipeline node (`ComponentNode.jsx`) can now hold a table schema, edited in a separate full-screen workspace opened from a small badge overlapping the node's icon (dashed "+" = no schema, filled amber grid icon + "N tables" row = schema attached). This intentionally does **not** live inline on the pipeline canvas — see the design rationale captured before implementation in the assistant's own memory (`erd_feature_design` note, session-local, not in this file) if that context is needed again.

- **Data model**: schema lives at `node.data.schema = { tables: Table[], relationshipOverrides: {} }` — no server/API changes were needed, since `nodes`/`edges` are stored as opaque JSONB (`server/db.supabase.js`) and pass through untouched.
- **Auto-detection, not manual line-drawing**: relationships are *derived*, not stored — `client/src/data/erd.js`'s `computeRelationships(tables, overrides)` scans every column's `fk` pointer and infers cardinality (1:N normally, 1:1 if the FK column is itself marked unique). A composite PK made of two+ FKs to different tables is flagged as a junction table (`isJunctionTable`) rather than drawn as a single N:N edge — it renders as its two natural 1:N edges plus an "M:N JOIN" tag on the table card. A user can override a relationship's cardinality by clicking its pill on the ERD canvas (`toggleRelationshipCardinality` cycles auto → override → back to auto).
- **New files**: `client/src/data/erd.js` (pure logic), `client/src/store/schemaSlice.js` (table/column CRUD + the ERD-workspace-open state, registered in `store/index.js`), `client/src/components/erd/` (`ErdWorkspace.jsx`, `nodes/TableNode.jsx`, `edges/RelationshipEdge.jsx` — a second, separate ReactFlow instance from the main pipeline canvas).
- **Visual language matches the pipeline canvas exactly**: same dark tokens (`#2A2119` node bg, `#4A3B2C` border, `#171310` canvas bg with the same dot grid), same edge-label-pill pattern as `LabeledEdge.jsx`. Relationship line color is a small fixed palette keyed to cardinality (1:N green, 1:1 blue) — deliberately **not** a free color picker; see the "avoid overbuilt customization" call in the assistant's memory if this gets revisited.
- **Table cards are draggable via a dedicated header handle** (`className="table-node-drag-handle"` on `TableNode.jsx`'s header + `dragHandle: '.table-node-drag-handle'` on the ReactFlow node object in `ErdWorkspace.jsx`) — the card is dense enough with inputs/buttons (all `nodrag`) that without a handle there's no usable surface to grab. The table name is a static label, double-click to rename (same convention as `LabeledEdge.jsx`'s edge labels) — a single click there drags instead of editing.
- **Gotcha (caused a real infinite loop, not just a bug): never fall back to an inline object literal (`schema || { tables: [] }`) inside a component that derives a `useMemo`/`useEffect` chain from it.** `ErdWorkspaceInner` used to do exactly that; since the fallback is a *new* object every render, `derivedNodes`'s `useMemo` (keyed on `schema.tables`) never stabilized for a node with no schema yet — which is every node before its first table — so its sync `useEffect` re-fired and re-set state every single render, forever. Fixed by hoisting the fallback to a module-level `EMPTY_SCHEMA` constant. Vitest's default test timeout did **not** catch this — a tight synchronous React render/effect loop starves the event loop before the timeout timer can fire, so the test process just hangs (had to bisect with a manual counter that throws past N iterations to even see it). `mergeFlowNodePositions` in `client/src/data/erd.js` was also hardened to return the *exact same array reference* when nothing changed, as defense in depth against the same class of bug recurring — a `useEffect` setter that returns a "new but equal" value every call is what turns any such loop from a perf nit into a hang.

## Testing infrastructure (added 2026-09-12)

The repo had test files (`vitest` syntax, e.g. `src/store/__tests__/canvasSlice.test.js`) but **no test runner was ever wired up** — `vitest` wasn't a dependency and there was no `test` script. Fixed as part of adding tests for the ERD feature:
- Added `vitest@^2.1.9` (pinned to the v2 line — v5 requires Vite 6/7/8, and this project is still on Vite 5), `jsdom`, `@testing-library/react@^14`, `@testing-library/jest-dom@^6` as client devDependencies, plus a `"test": "vitest run"` script in `client/package.json`. No `vitest.config.js` was added — per-file `// @vitest-environment jsdom` comments opt individual component tests into jsdom, keeping the default (fast, node) environment for pure-logic tests.
- **Testing ReactFlow components in jsdom requires three polyfills**, not just one — discovered the hard way in `client/src/components/erd/__tests__/ErdWorkspace.test.jsx`: (1) `ResizeObserver` (missing entirely in jsdom), (2) `DOMMatrixReadOnly` (ReactFlow reads the viewport's zoom from `new DOMMatrixReadOnly(computedStyle.transform).m22`), and (3) `HTMLElement.prototype.offsetWidth`/`offsetHeight` (jsdom does no layout, so these are always 0, and ReactFlow keeps a node `visibility: hidden` — invisible to `getByRole` — until it measures a nonzero size). All three are needed together; missing any one leaves nodes permanently hidden from accessibility queries even though they're present in the raw DOM.
- **Found two pre-existing, unrelated broken tests** (not fixed — out of scope for the ERD work, flagged here so they're not mistaken for new regressions): `src/store/__tests__/diagramSlice.test.js` has 2 failing assertions (`saveDiagram`'s axios call-signature expectations don't match the current implementation). `src/hooks/__tests__/useCurrentUser.test.js` imports `@clerk/clerk-react`, which is no longer a dependency (per commit `72045a6f "remove dead Clerk-based collab prototype"`) — the hook itself (`src/hooks/useCurrentUser.js`) is still live code, still imported by `src/components/collaboration/CommentsPanel.jsx`, but `CommentsPanel` isn't mounted anywhere in the app, so this doesn't break the running app, only its own test.

## Guardrails on `/api/generate` and `/api/edit` (server/index.js)

1. Input validation: non-empty prompt, `MAX_PROMPT_LENGTH = 4000` chars.
2. Rate limiting: 10 requests/IP/24h (`aiRateLimit`).
3. Site-wide circuit breaker: 200 AI calls/day total (`aiDailyCap`, configurable via `DAILY_AI_CALL_LIMIT`).
4. Semantic buildability/actionability check baked into the system prompts — model must identify a real subject + purpose (generate) or a real target + concrete change (edit) before building, else must return `needsClarification`.
5. `SKIP_CLARIFICATION` token — explicit override to force a best-effort build instead of an ask-loop.
6. `extractJSON()` — tolerant JSON extraction from raw model text (strips preamble/markdown fences).
7. `JSON.parse` wrapped in try/catch — malformed output returns a graceful SSE error, not a crash.
8. `needsClarification` shape validation before forwarding to the client.
9. Component-type whitelist enforcement — invalid `componentType` silently coerced to `rest_api`.
10. Edge-type normalization — all edges forced to `type: 'labeled'`.
11. API-error mapping — Anthropic errors translated to user-facing messages (401/404/429) without leaking internals.
